# 谁拥有查询、工具和历史？

同一个模型在 Quick Chat、桌面 ZPI 和自己的 Node 程序里都能回答问题，为什么可用工具不一样？相同的是执行引擎，而不是一套预装好的工作台。

**普通应用**调用公共 `query`，由 SDK 创建并管理会话。应用决定模型、工作目录、工具目录、是否收集本机资源和是否持久化。`tools` 描述模型看得见什么，`canUseTool` 管某一次调用，操作系统权限才决定进程能做什么。给模型一段「请勿修改」的系统提示，并不构成只读保证。

**外部宿主**可能已经有索引历史、当前模型选择、后台进程和自己的 UI。再创建第二个写入者会让两个视图互相矛盾。因此它用 `/host` 创建会话，公共 Query 只借用及投影消息；真实工具和循环策略在创建原生会话时装配。索引式 `TranscriptStore` 是宿主的存储接口，公共 `SessionStore` 是跟随本地写入的镜像，它们不是可互换的同一个适配器。

**两个产品有自己的取舍。** 桌面直接使用底层引擎并装配自己的插件；独立 Quick Chat 用公共 SDK，把会话留在内存，只开放两个开关。安装 SDK 不会带来两者的窗口、快捷键或账号设置。官网的 SDK 小窗口则连模型都不调用，不能当成 SDK 的真实耗时、账单或返回协议。

据此选入口：只想跑一轮，回到[第一次查询](../tutorial/first-query.md)；已有真实会话服务，再看[/host 对照](../reference/host.md)。
