# 备份数据并定位一次失败

出错时最有用的是保住现场，并分清失败发生在启动、模型请求还是文件执行。不要用重装或清空目录作为第一步。

## 先留一份完整备份 {#backup}

1. 记下运行的是正式版还是 Preview，是否设置了绝对路径 `ZPI_DATA_DIR`。macOS 正式版默认在 `~/Library/Application Support/ZPI/`；Preview 使用不同的数据根。项目源文件、外部技能或命令的链接源不一定在这里。
2. 正常退出所有使用该数据根的进程，再复制**整个数据根**及另需保留的项目文件。不要只复制运行中数据库的一个 `.sqlite` 文件；WAL、附件、快照和当前数据代都可能有关联。
3. 验证备份可读，记录原路径和软件版本；恢复前也先备份目标目录。移到另一台机器后，系统密钥存储可能不能解密原凭据，准备重新配置账号。不要在两个进程间共享同一个可写根。

## 按症状定位

| 看到什么 | 先查哪里 | 如何判断下一步 |
| --- | --- | --- |
| CLI 还没开窗就退出 | `node -v`、启动终端的错误、平台、Electron/PTY 的安装脚本 | 对照[启动参考](../reference/setup.md)。此时换模型无用 |
| 应用提示数据被占用 | 还有没有正式版、Preview 或另一个同根进程 | 正常退出持有者后重试；不要直接删锁或数据库 |
| 模型报错/等不到首个事件 | 任务里的失败记录、设置中的提供商和模型、网络和代理 | 用同一模型发送一句短请求。认证失败先重新配置，过载先等待；不要重复派发已生效的文件工具 |
| 文件没变，或回退被拒绝 | 当前任务的 cwd、工具输出、审查来源、文件是否被别的程序修改 | 比较实际文件，不用「重新生成回答」覆盖别人后改的内容 |
| 用量看似不准 | 区分服务端用量和本地上下文估算；加速与模型可能变更费用 | 报告问题时记版本、提供商、错误类型和时间，移除密钥、私有路径及对话内容 |

**本机诊断位置。** 在实际数据根下查 `agent/logs/error.log`；约 5 MiB 轮转为 `error.log.1`。按故障时间、来源和会话 ID 查相关行，`model.responses_transport` 用于区分连接复用和回退。日志会屏蔽常见密钥格式，分享前仍须人工检查，不要直接上传数据根。
