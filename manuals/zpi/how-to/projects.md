# 把任务放进正确的目录和工作树

两个任务都叫「修复文档」，但一个应该写原项目，另一个要试新方案。先选工作位置，比最后找错文件容易得多。

## 在已有目录工作

1. 左侧「项目」旁点 **添加项目**，在系统目录选择器选项目根目录。要接着做已有任务，点原来的任务，不要另开同名草稿。
2. 用项目行的新建入口开任务。发出第一条消息前检查环境；右侧新开终端运行 `pwd`，或从文件树认出只有该目录才有的文件。
3. 在任务菜单中重命名、置顶，或用任务列表的组织方式在项目、时间线和分组间切换。移动到列表分组是整理视图，不会移动磁盘上的文件。没有项目的任务也有自己的工作目录，不会因为你后来展开另一个项目而自动改绑。

## 用独立工作树试验

在 **Git 项目中的新草稿 → 配置本地环境 → 新工作树** 打开开关并选起始分支，再首次发送。ZPI 从选定提交创建独立检出目录，初始为 detached HEAD，并不会自动创建同名分支。先核对真实路径与提交，再改文件。同一仓库有多个工作树时，审查的是任务实际工作目录。没有 Git 或仓库无可用基础提交时，先处理仓库状态，或回到本地目录练习。

归档涉及受管工作树清理。未提交文件（含被忽略文件）、独有提交、仍占用它的终端或其他任务，都可能阻止清理。先保留修改并关停使用者，不要为通过归档而删除未核对的文件。准备收工时见[查找、归档和恢复](search-archive.md)。
