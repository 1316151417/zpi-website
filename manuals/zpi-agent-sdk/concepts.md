# concepts | 应用开发
## configuration | 配置你的 Agent
先确定三件事：向哪个模型发请求，模型能使用哪些工具，以及有哪些理由应该停止。连接正常不等于工具已授权；指定 `cwd` 也不等于建立了安全沙箱。

### 从没有副作用的查询开始

使用[快速开始](../start/first.html)中的 `{model:'deepseek', tools:[], persistSession:false}`，在同一个终端设置服务端凭据。只需要填充模型选择器时，用 `initializationResult()` 检查注册目录；列出模型不验证远端账号权限。要测试鉴权再真正发送一句话。

### 按需求增加配置

| 需求 | 配置 | 验收 |
|---|---|---|
| 固定某一款模型 | 将 `model` 设为完整的 `provider/model-id` | 从 `supportedModels()` 复制 value，在 init 确认实际模型 |
| 使用自有模型服务 | 用 `zpi.providers` 注册协议、地址、密钥和模型元数据 | 分别验证发现与请求；明确成本元数据是否真实 |
| 查询业务数据 | 在 `zpi.customTools` 注册函数，并用 `tools` 选择名称 | init 有该名称，消息流也有真实调用和结果 |
| 让项目规则生效 | 显式选择 `cwd` 和 `settingSources:['project']` | 空目录先做对照，再试有项目说明的目录 |
| 限制一轮的代价 | `maxTurns` 管模型循环，`maxBudgetUsd` 管已估算花费，`abortController` 管整体取消 | 区分请求超时、预算耗尽和用户中断 |

### 确定唯一的配置所有者

传入 `zpi.modelRuntime` 时，应先在该实例上注册模型，不再指望 SDK 为它补注册提供商。如果借入的是已有 `zpi.session`，工具、预算、轮数和钩子在**创建宿主会话时**装配，不能在借用时重新覆盖。逐字段的类型、默认值和互斥条件见 [Options](../typescript.html#options)。

## sessions | 使用会话
一次 Query 是运行对象，一段会话是一份可以延续的历史。在相同工作目录创建两个查询，不会让第二个查询自动接续第一个。先决定用户想**追问、恢复还是分叉**。

| 目的 | 使用 | 检查结果 |
|---|---|---|
| 在同一个窗口连续提问 | 保留对象和消费循环，向同一输入流追加新消息 | 每轮分别收到 result，session_id 一致 |
| 程序重启后继续 | 将已保存的 `session_id` 与相同存储范围传给 `resume` | 恢复原 ID，能引用上一轮材料 |
| 保留原方案再试另一种 | 按消息 UUID 调 `forkSession`，用新 ID 继续 | 有两份独立历史，不自动复制项目文件 |
| 做一次无状态问答 | 创建时 `persistSession:false` | 不承诺重启后能找回 |

### 为应用接一条完整的恢复路径

首次成功后把会话 ID 与应用中认证的用户绑定。列表调用 `listSessions({dir,…})`；打开已有条目用 `getSessionMessages(id,scope)`，读取历史不需要耗费模型请求。用户点击继续时，先在服务端验证所有权，再传 `resume:id`。不要用“最后活动的会话”替用户猜 ID。

### 消息和文件各归谁管理？

分叉复制消息前缀，重命名改变显示名，文件检查点才尝试恢复受跟踪的写入。以上操作都不代替 Git 工作树或撤销外部订单交易。跨进程的完整验证见[恢复练习](../history/reopen.html)；需要跨机器恢复则看[外部存储](../storage/adapter.html)。

## permissions | 控制工具权限
先问三个问题：工具实现是否存在，模型看得见什么，这一次调用是否获准。`zpi.customTools` 用来注册业务实现，`tools` 用来选择名称，规则和回调用来处理一次真实调用。只需要读取订单时，不必给模型通用的文件和命令工具。

### 决策顺序

1. 先检查 `disallowedTools`。禁止裸工具名还会将它移出可见集合；带参数的拒绝规则需要实际输入才能判断。
2. 若无拒绝并命中 `allowedTools`，跳过 `canUseTool`，视为预批准。它并不是可见性白名单。
3. 其余调用才交给 `canUseTool`。应用返回 allow 或带原因的 deny。没有这个回调默认允许，SDK 不会弹出内置确认框。

### 把用户选择接回原请求

使用[审批适配器](../tools/approve.html)，把 `requestId`、工具名和准备访问的材料展示给有权确认的人。等待时监听取消信号；超时或用户取消就拒绝，不要默认为同意。要限制读取范围，可在批准时返回 `updatedInput`，执行方仍会检查改写后的参数。

测试时特意拒绝一次：看 `permission_denials` 是否对应本次调用，并核对真实文件或业务数据未变；整轮助手可以解释拒绝原因，因而仍可能成功返回文本。处理不可信用户时，路径规则和提示词不能代替进程隔离或数据库权限。
