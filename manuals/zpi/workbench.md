# layout | 工作区与右侧面板
## collapse | 收起侧栏，专心看当前内容
需要更多对话空间时，点顶栏左侧栏按钮隐藏任务列表，或用 Command+[。右侧预览也有自己的开关（Command+]），两边可单独操作。

隐藏不是关闭标签，也不是停止任务。再点同一按钮应能回到之前的文件或任务列表，不必重新定位。
## split | 拖动分隔线调整三栏宽度
指针移到任务列表与聊天、或聊天与右面板之间的分界，出现调宽光标后拖动。想同时看问题和代码时，把列表缩到能认出任务名，把剩余空间留给中间和右侧。

达到最小宽度后不要继续拖；临时需要完整宽度可收起一栏。调宽面板不会放大文字，阅读字号在界面设置里调整。
## tabs | 查找和整理右侧标签页
点右栏 **＋**，选择文件、浏览器、终端、审查或辅助对话。打开多个文件后，可以拖动标签排序，或打开标签总览按标题搜索。

要清理标签，先看清「关闭标签」「关闭其他标签」与「关闭所有标签」。特别是终端：切换标签保留终端进程，关闭终端标签则不是单纯隐藏。
## full | 在完整视图中边看文件边提问
打开一个右侧文件或网页，使用 **完整视图**（Mac 默认 Shift+Command+F）。内容展开后，从浮动控件展开编辑器，提出针对眼前内容的问题，再最小化编辑器。

再用完整视图开关返回平时的布局。这个操作扩大内容区，不会把任务历史复制到另一个窗口。

# files | 文件与代码预览
## search | 在文件树里找到文件
打开右栏 **＋ → 文件**，在文件目录的搜索框输入文件名的一部分。找到结果后先看父目录，再打开；同名文件尤其要核对路径。

搜索限定在任务工作区。若提示已搜索范围内无匹配，清空查询、刷新文件树，检查是否进了工作树或默认目录，再扩大搜索范围。
## changed | 在文件树中只看变更文件
在文件目录栏点击 **仅显示变更文件**。这个筛选适合从许多目录中找出正在修改的文件；再次点击「显示全部文件」恢复完整列表。

没有显示不等于文件不存在。要核对某一轮到底改了几行，打开[上一轮更改](../review/last-turn.html)，不要把树的过滤结果当作差异报告。
## card | 从助手回复打开生成的文件
在文件卡片上先核对文件名，再点主按钮 **打开**。右栏应该出现文件内容；HTML 等可预览结果还可以用对应的浏览器入口查看。

按钮旁的小箭头是打开方式菜单，不会重复执行生成任务。如果结果打不开，先确认文件确实已经写入以及路径仍然存在。
## source | 在渲染结果和源码之间切换
打开 Markdown 或 SVG 等支持双视图的文件，从预览标题栏的菜单选择「源码」或「代码」。这样可以区分标记本身错误与显示效果不对。

要检查交付给阅读者的版本，再切回「预览」。没有双视图的文件不会显示同样的入口；这不是源文件编辑器。
## external | 用外部编辑器或默认程序打开
在文件卡片的打开方式菜单、文件树右键菜单或预览的编辑器按钮中选择本机程序。系统默认程序适合打开文档，代码文件则可选已安装的编辑器。

核对外部窗口里打开的完整路径。外部修改仍然写到真实文件；下一轮让 ZPI 编辑前，先让它读取更新后的内容。
## paths | 复制相对路径或绝对路径
在文件菜单选择「复制相对路径」可得到项目内位置，适合写给同一个项目的同事。要用终端精确打开本机文件或确认工作树，选「复制绝对路径」。

粘贴到文本框先检查结果；绝对路径可能包含用户名。发到外部之前，删掉不需要透露的本机信息。

# documents | 文档与演示文稿
## pdf | 跳到 PDF 的某一页
从右栏文件树打开 PDF，待页码出现后在页码框输入目标页。用缩放控件放大一张图，再移动到下一页检查上下文。

预览不等于修改 PDF，也不会自动让模型阅读指定页。若要提问，明确给出文件、页码和图表标题。
## word | 核对 Word 文档的排版
在文件树打开 Word 文档，等内置预览完成后检查分页、段落和图像。让 ZPI 生成报告后，先用这种方式看读者拿到的文档，而不是只看对话里的摘要。

字体或复杂布局需要精确验收时，从打开方式菜单交给本机办公软件。看到预览不会改变原文档。
## sheets | 在表格预览中切换工作表
打开电子表格后，点击工作表标签，再核对列名和目标单元格。报告里说的“总计”可能位于不同表；提问时带上文件名、工作表和单元格范围。

切换表只改变正在查看的内容，不会把单元格直接写回文件。需要编辑时在任务里明确提出要求，再重新打开结果。
## slides | 阅读 PowerPoint 幻灯片
打开 `.pptx` 后从缩略图选择一页，或用页码框跳转。放大查看文字有无裁切，翻到相邻两页比较布局，不用逐页截图贴进聊天。

如果文件为空或渲染失败，先用默认程序确认文件能打开。要指明某个元素，接着用[元素选择](element.html)。
## element | 让 ZPI 只改幻灯片里的一个元素
在幻灯片预览中点 **选择元素**，再点想改的标题或图形。选 **AI 编辑**，填写「把这段标题缩成一行，不改另外两栏」，按 **添加到对话**。

先核对进入草稿的页码、对象和要求，再发送。点选或添加到对话本身不会改文件；完成后重新预览同一页检查结果。
## export | 把演示文稿导出为 PDF
打开 PowerPoint 预览并确认页序，点击工具栏的 **导出 PDF**，按系统提示选目标文件。给输出取不同名称，便于区分源文稿与交付件。

用 PDF 预览独立打开导出件，检查页数和最容易溢出的那一页。要修订内容，应改原演示文稿并再次导出。

# review | 审查文件改动
## last-turn | 只看 ZPI 刚才这一轮改了什么
等回复结束，从文件更改摘要打开文件，或在右栏选 **审查 → 上一轮更改**。先看文件列表，再展开目标文件，对照被删去的旧行与新增行。

这个来源使用任务的文件变更快照，不要求目录是 Git 仓库。最简单的验收是要求只改一行，确认列表里只有预期文件，而且无关行没有变化。
## unstaged | 检查尚未加入暂存区的改动
在 Git 项目的审查来源中选 **未暂存**。核对工作目录与暂存区之间的差异；你自己在外部编辑器做的修改也可能在这里，它不是模型专属视图。

若某个文件已经暂存，切到「已暂存」再找。这里只进行审阅，打开差异不会替你执行 `git add`。
## staged | 检查已暂存、将随提交带走的内容
在 Git 仓库里选 **审查 → 已暂存**。逐个展开文件，核对准备提交的版本；同一个文件可能同时还有另一批未暂存编辑。

要比较在编辑器中看到的最新文本，再查看未暂存来源。看到行被列出只是证明暂存区有改动，并没有创建提交。
## branch | 对比当前分支与上游的改动
在有关联上游的仓库打开「全部分支更改」。它比较上游与当前分支的共同起点到当前提交，不混入尚未提交的工作区修改。

如果你刚改完文件却还没有提交，这里可能为空。要查刚才那一轮，换「上一轮更改」；确认上游关系可在终端用 `git branch -vv` 查看。
## empty | 审查列表为什么是空的？
先看当前来源，再核对目录。没有 Git 的练习文件夹仍能看有快照的「上一轮更改」，但不能提供已暂存差异。只读了一份文件的一轮也不会产生写入快照。

确认有外部变更却没刷新时，点审查的刷新按钮；核对是否处于另一个工作树。不要为了出现差异就执行重置、提交或更改源文件。

# browser | 浏览器预览
## html | 打开 ZPI 生成的 HTML
在任务里让 ZPI 写一个本地 HTML 文件。写入完成后从结果卡片打开，或从文件树菜单选 **用内置浏览器打开**。检查地址对应刚才的文件，再实际点击页面上的控件。

看到 HTML 源码时，你打开的是文件源码视图；无需重新生成文件，改从浏览器入口打开即可。
## localhost | 在右栏预览本机网页应用
先按项目说明在正确目录启动开发服务。终端打印本机网址后，打开右栏 **＋ → 浏览器**，把包含端口的完整地址贴到地址栏。

地址能打开才说明服务在运行；新开浏览器标签不会启动服务。更新页面用刷新，连接失败时回到启动服务的终端检查输出。
## external | 把当前页面交给系统浏览器
在内置浏览器确认地址，点击工具栏的 **在外部浏览器打开**。系统浏览器应打开同一个 URL，适合检查需要用完整浏览器交互的页面。

不会自动迁移本机服务，也不会把 `localhost` 变成别人能访问的网址。给同事发送链接前先确认地址实际可达。

# terminal | 终端与后台命令
## interactive | 在右侧终端亲自运行命令
选 **＋ → 终端**，输入 `pwd` 后回车，确认工作目录，再输入 `printf 'ok\n'`。应在这个标签里看到 `ok`；消息输入框不会因此出现新的助手回复。

你在直接操作终端，不是通过模型执行。切换标签会保留终端，关闭会销毁它；要中断前台命令先在终端按 Ctrl+C。
## background | 让长时间作业在后台运行
先确认「后台命令」插件对新任务可用。要求 ZPI「按项目说明启动开发服务，放到后台，告诉我任务 ID」。等工具返回后台任务标识后再继续聊天。

把 ID 和作业描述对应起来。普通终端里自己启动的命令不会因此出现在助手的后台作业列表里。
## output | 查看一项后台作业的输出
展开任务状态，选择相应命令，打开后台任务输出。看最新几行，核对服务地址或明确的错误；也可让 ZPI 按该 `task_id` 查输出。

完成时会有状态变化，不必让模型连续轮询。历史日志仍然可读并不等于进程还活着。
## stop | 只停止指定后台命令
先在状态面板核对描述和 ID。让 ZPI「只停止这个后台任务」，使用当前任务返回的 `task_id`。看同一项离开运行态，而其他作业没有发生变化。

别用停止主回复替代停止作业，也别用历史 PID 在系统里盲目结束进程。应用异常退出后的旧记录不是可重新接管的命令。
