# start | 第一次使用 ZPI
## purpose | ZPI Desktop 是什么？
ZPI 是一个在本机工作目录里做事的助手。你不必在“聊天”和“编程”之间切换：问「这个文件写了什么」，它可以读取文件；要求「把这句改短」，它可以直接编辑。两次请求用的是同一个输入框，区别在于你交付了什么任务。

左边选任务，中间说要求、看执行过程，右边在有东西要检查时才打开。先学会读、写、编辑和执行这四种动作。若手头的一件事不需要查网页、委派或记忆，就不必配置它们。

第一次练习只需要一个模型和一个可丢弃的文件夹。完成[改一行文字](first-edit.html)后，你就已经走完了日常工作的一整轮。

## install | 安装并启动 ZPI
先在终端运行 `node -v`，应看到 `v24.x.x`。以下示例以 Apple Silicon Mac 为例；Desktop 不支持 Windows。另开一个终端标签运行：

```sh
npx @zpi-dev/desktop
```

首次运行需要下载包，终端可能先询问是否继续。等桌面窗口出现，不要关闭启动它的终端。窗口里应该有新建任务入口；输入框还没有模型并不代表安装失败。

要确认实际运行的版本，用 `npx @zpi-dev/desktop --version`。接下来[连接第一个模型](first-model.html)。

## first-model | 连接第一个模型：以 DeepSeek 为例
准备你自己的 **DeepSeek API Key**。它是模型服务的凭据，不是发给助手的消息；真实查询可能产生费用。

1. 在窗口左下角打开 **设置 → 模型**。选择 **新增提供商**，在预置提供商里选 **DeepSeek**；已有这一项就直接选它。
2. 保留预置的地址和 API 格式。在 **API Key** 输入框填入密钥，确认提供商已启用，列表里至少一个模型的开关已打开，然后点 **保存提供商**。
3. 点 **返回任务**。在任务输入框的模型选择器中选刚启用的 DeepSeek 模型，发送「只回复：连接成功」。看到这个任务出现助手回复，才算完成验证。模型没有逐字照抄不是连接失败；鉴权错误才需要回头核对密钥。

> 已有可用的 **ChatGPT 订阅**？也可以走[浏览器登录并授权 ChatGPT](../models/chatgpt.html)，不必为了这次练习购买 DeepSeek。不要把 ChatGPT 登录密码填到 API Key 框。这里也不是「设置 → 联网搜索」：普通对话不需要开搜索。

## first-edit | 第一次任务：只改一行，亲自检查
在 Mac 终端准备一个全新的练习目录。保留这个标签，最后还要回来看结果。

```sh
practice=$(mktemp -d "${TMPDIR:-/tmp}/zpi-practice.XXXXXX")
printf '状态：未开始\n保留：蓝色\n' > "$practice/note.txt"
open "$practice"
```

1. 在 ZPI 左栏点 **添加项目**，选刚刚打开的文件夹。从该项目新建任务，不选「新工作树」。找不到目录时，用 `printf '%s\n' "$practice"` 查看完整路径。
2. 确认已[连接模型](first-model.html)，输入：「读取 note.txt，只把第一行改成『状态：已完成』。保留第二行，不新增文件。」按 **Enter**。
3. 等这一轮结束，点回复下的文件卡片，或打开 **审查 → 上一轮更改**。你应看到第一行的一删一增，不应看到第二行变化。这一步不需要 Git。
4. 回到原终端执行 `cat "$practice/note.txt"`：第一行是 `状态：已完成`，第二行仍是 `保留：蓝色`。回复说“已完成”但文件没变时，先核对任务目录，再看有没有真正发生编辑或写入。

## trust | 第一次发送前，看清 ZPI 能动到什么
在终端能以你身份访问的文件，并不会因为换到聊天窗口就自动受到保护。项目选择决定从哪里开始工作，不是把进程锁在那个目录里的安全沙箱。模型也可能收到完成请求所需的文件内容。

第一次用新模型、新插件或陌生项目时，用不含个人资料和密钥的练习副本；不要一上来就在唯一的工作目录里要求批量删除。要真正限制文件访问，使用受限的系统账号或隔离环境，而不是只写一句「请勿修改」。

停止回复不会撤销已经完成的写入。先用[上一轮更改](../review/last-turn.html)核对文件，然后决定是否回退。
