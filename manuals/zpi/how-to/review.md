# 如何查看刚才改了什么

回复写着「已完成」还不够，先看哪一行真的变了。检查一次工具、一次回复，或整个 Git 工作区，用的是三个不同的入口。

## 检查这一轮 {#last-turn}

1. 留在产生修改的任务。回复底部出现文件变更摘要时，展开它，点文件名。要看单次操作，展开对应的编辑工具卡，而不是选仓库总览。
2. 若摘要已经滚出屏幕，打开右侧面板，在新标签中选 **审查**，把「审查来源」换成 **上一轮更改**。它来自当前任务的工具快照，不要求目录是 Git 仓库。
3. 展开文件，核对路径和增删行。相同文件多次修改时，轮末看到的是本轮前后净差异；中途改回原值不应当算成最终新增。

## 检查整个仓库 {#git}

在同一来源选择器选 **未暂存** 看工作区、选 **已暂存** 看索引、选 **全部分支更改** 看当前 HEAD 相对上游的三点比较。别把暂存区已有改动归因于刚才那次回复。没有上游时分支来源可能为空。在审查里查找文件或内容，展开具体文件再判断。

## 没有 Diff，或想恢复旧内容

没有变化时先确认任务、轮次和来源。「上一轮」指当前任务最新的一轮，而不是最近有写入的那一轮。改完后若又问了一个只读问题，这里为空是正常的；回到实际产生改动的历史回复，打开那条回复的变更摘要。终端或其他程序写入不一定有工具快照。在文件树打开实际文件；大文件、二进制或缺失快照可能只有摘要。审查是读操作，不等于 Git 提交。

需要重做最后一轮时，从**最新一轮用户消息**的编辑入口检查可用回退选项；不是所有旧消息都能编辑。先保存你自己后加的修改；检测到磁盘冲突时不要强行覆盖，回到文件和 Git 差异核对。只想换一种回答，优先[从完成的回复分叉](conversation.md#fork)，不必回退磁盘。
