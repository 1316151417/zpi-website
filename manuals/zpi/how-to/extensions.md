# 给一个项目配置扩展，而不意外影响别的任务

你希望所有新任务都能看到项目约定，但只在这个项目里触发某个自动化。不要为两件事都安装能执行命令的插件。

## 只说明约定

把简短、可长期执行的项目要求写在项目根 `AGENTS.md`，或项目的 `.zpi/AGENTS.md`。例如「修改示例文档时保留第二行」。用户级来源还有 `~/.agents/AGENTS.md` 和 `~/.zpi/AGENTS.md`。显式绑定该项目，新开任务并核对指令；一个普通目录里的任意 Markdown 不会自动变成全局规则。要按需调用多步做法，用[技能或命令](customize.md)。

## 在一个生命周期事件上做事

1. 打开 **设置 → 钩子**，把「钩子范围」选为目标项目而非「本机 · 用户」。用户钩子也会应用于该项目。点「新建」。
2. 选择事件（例如 `PostToolUse`）、需要时填写匹配条件，选进程或命令，填入你已审阅的程序与参数。先在练习项目选不写文件、不发网络的动作，设置合理超时。不要把可执行文件路径与整段 Shell 语句混为一项，也不要把外部输入直接拼成命令。
3. 保存并启用，开一个新任务触发所选事件。在该范围的钩子列表核对已启用，按你所选程序的可观察结果验证它触发，再确认另一个项目的新任务没有该项目钩子。若没有触发，查事件、匹配条件、范围与启用状态，不要因此改用更高系统权限。先关钩子并新开任务就能验证是否由它引起问题。

## 明确导入一组能力

到 **设置 → 插件 → 添加 → 从本地文件夹添加** 选择已审阅的插件目录。先看来源、贡献的命令/技能/钩子和错误提示，再决定是否启用；「已安装」与「内置插件」是两组。导入不代表支持插件 UI、远程市场或所有其他产品的插件协议。修改后用新任务验证首次装配；旧任务不会因开关变化立刻新增工具。

如果只是想让模型在有歧义时提问，不需导入外部插件：检查内置的「向用户提问」。要比较提问、协作和后台命令各贡献哪些名称，回到[桌面工具表](../reference/tools.md)。
