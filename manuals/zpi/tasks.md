# organize | 找到和整理任务
## search | 用命令中心找任务、文件或操作
按 **Command+K** 打开命令中心。输入任务名片段，选择任务结果；要找工作文件就核对文件结果的路径；要执行动作则选操作项。没输入时也可从最近任务或最近变更开始。

这不同于 Command+F 在当前任务里找一句话。若任务已被归档，改到「设置 → 已归档任务」搜索。
## rename | 给任务取一个能找回来的名字
打开任务菜单选 **重命名任务**，把“试试看”改成以后会搜的目标，例如“对齐发票模板页脚”。确认左栏标题更新，再用新名字搜索一次。

会话标题插件可以自动起名，但手动命名会保留。标题不是磁盘目录名，重命名不会迁移项目。
## pin | 把每天要回访的任务置顶
在目标任务的菜单选 **置顶**，到左栏的置顶区核对标题。Mac 上可以用 Command+1 至 Command+5 切到对应位置的置顶任务。

不再需要优先显示时选取消置顶，不必归档。置顶还会影响自动归档的筛选，因此不要用置顶代替长期备份。
## group | 给相关任务建一个分组
从筛选视图切换至 **按分组**，点新建分组，取一个代表工作主题的名字。把相关任务放入该组，展开后逐个核对；也可从组旁新建任务。

分组整理的是任务列表，不会为每个组创建磁盘目录。文件要写到哪里，仍由项目和工作目录决定。
## views | 切换任务列表的排列方式
点任务列表的 **筛选视图**。要定位某个仓库选「按项目」；要按自己整理的主题找选「按分组」；要回到刚做的工作选「最近更新」。

切换只改变列表组织方式。任务看似消失时，先展开项目或分组，再用命令中心搜索，不要为了找回列表而重复创建任务。

# archive | 归档与恢复
## archive | 归档一项已经结束的工作
确认任务不再运行，从任务菜单选择 **归档任务**。任务离开普通列表后，在「设置 → 已归档任务」搜原来的标题验证。

归档是暂时收起来，不是永久删除。如果任务有工作树，归档前还有防止丢失改动的检查；遇到跳过提示先检查原因。
## restore | 找回并恢复已归档任务
打开已归档任务页，按标题搜索，核对项目与任务后点 **恢复**。回到工作区，应该能打开原来的对话，不必重新复制提示词。

工作树任务可能需要重建环境。若失败，不要用同名的新任务覆盖线索；先检查原路径、分支和仓库是否可用。
## auto | 设置自动归档，保留还在用的任务
在已归档任务页打开归档管理，启用 **自动归档旧会话** 并选保留时长。保留期按最后活动计算，不是每隔一段时间删除全部历史。

运行中、未读、置顶、当前打开、有草稿或队列的任务会跳过。检查一个仍在普通列表的旧任务时先核对这些条件，再看是否卡在工作树安全检查。
## delete | 永久删除一项任务前检查影响
在已归档任务里选中目标，核对标题和项目，阅读删除确认。会话记录、图片附件和文件变更快照会一起删除，不能再用「恢复」找回；项目里的源文件保留。

想让列表简洁，用归档就够了。需要保留历史时先退出应用并备份实际数据目录，不要用真实的重要任务来试删除。

# worktrees | 用 Git 工作树隔离修改
## create | 为新任务创建独立工作树
从 Git 项目新建任务，在首次发送前打开 **配置本地环境 → 新工作树**。确认起始点后发出要求；从任务目录核对它使用的是新的工作树，而不是原仓库目录。

在工作树中修改一个练习文件，在原目录查看它不应跟着变化。非 Git 文件夹不能靠这个开关创建同样的隔离环境。
## base | 从指定分支或提交开始
创建工作树时打开「起始分支」，从当前提交、本地分支或本地已同步的远程分支里选择。查看分支名与提交，尤其注意同名分支来自哪里。

选择当前提交会以该提交为起点，不包含工作区尚未提交的修改。分支列表不会代替你向远端同步，找不到远程分支先核对本地 Git 状态。
## fork-files | 分叉以后，为什么文件还是同一份？
分叉复制的是截止到某条回复的对话前缀。分别打开两个任务的目录信息；如果完整路径相同，从任意一边写 `note.txt` 都是在写同一个文件。

只比较答复思路时分叉就够了。准备并行试两种代码实现时，在写之前另外从项目创建独立工作树，不要指望对话标题里的 `Fork of` 隔离文件。
## keep | 归档时为什么保留了工作树？
从归档的处理结果查看被跳过的任务，再到对应工作树核对未提交文件、被忽略文件、独有提交、打开的终端以及是否还有别的任务在用它。

先自己保存需要的内容、关闭不再用的终端，再尝试归档。不要为了通过检查就强制删除目录；它可能是某次工作的唯一副本。
## rebuild | 恢复任务时重建原工作树
在已归档任务页点恢复。对于归档时已安全清理的工作树，ZPI 会尝试按原来的路径、分支与提交重建；这与把聊天记录显示回来是两件事。

恢复后先检查终端里的 `pwd` 和 Git 状态，再续写。原位置已被占用或提交无法定位时，先保留现场和错误信息，不要覆盖同名目录。
